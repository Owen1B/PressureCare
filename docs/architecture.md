# 压力估计与反馈控制

本文对照压力采集、滤波、PID、模式状态机和 UI 桥接的实现说明计算过程。源码依据为 [`fcc48ca9`](https://github.com/Owen1B/PressureCare/tree/fcc48ca97335ec47a2daddf350d13a3250085b61)。

## 数据与模块

| 模块 | 输入 | 输出与职责 |
| --- | --- | --- |
| 压力 HAL | ADC 原始值与校准参数 | 电压换算和整数 kPa 压力。 |
| Kalman 滤波 | 压力观测、`Q/R` | 浮点压力估计及内部方差。 |
| PID | 目标压力、反馈压力、时间间隔 | 有界控制量。 |
| 泵 HAL | PWM 计数与频率 | I2C 写入 PCA9685。 |
| 模式状态机 | 工作/休息时长、秒级计数 | 当前工作阶段和控制动作。 |
| UI 与核心接口 | 设置、运行状态快照 | 显示更新、参数修改与保存。 |

控制数据保存在 [`npwt_system_t`](../main/npwt_core.h)，分为设置与运行状态两部分。核心接口通过互斥锁读写这些结构体。

## 压力估计

### ADC 与压力换算

[`hal_pressure_sensor_read`](../main/hal/hal_pressure_sensor.c) 使用 ADC oneshot 读取通道，优先通过 ESP-IDF 的电压校准接口取得 mV；回退路径采用 `adc_raw × 3300 / 4095`。随后执行线性换算：

$$
p=(V-V_0)c,
$$

其中 `V` 以 mV 计，示例配置为 `V0=480`、`c=-0.0495`，压力单位为 kPa。它们对应当前代码参数，换用传感器或采样电路时需要重新标定。

HAL 将压力四舍五入后写入 `int16_t`，滤波结果又存入整数类型的 `current_pressure`。因此数据路径中存在两次整数化；PID 接收到的是运行状态中的整数反馈值。该表示方式决定读数分辨率，测量精度仍由标定与参考仪器的对照给出。

### 标量 Kalman 滤波

[`kalman_filter_update`](../main/algorithms/kalman_filter.c) 采用单位状态转移和直接观测模型。每次更新为：

$$
P^-_k=P_{k-1}+Q,\qquad K_k=\frac{P^-_k}{P^-_k+R},
$$
$$
\hat p_k=\hat p_{k-1}+K_k(z_k-\hat p_{k-1}),\qquad P_k=(1-K_k)P^-_k.
$$

`Q` 按调用次数累加，`R` 为观测噪声参数。当前配置为 `Q=0.01`、`R=0.1`，初始 `P=1`。采样频率改变时，应重新评估每步 `Q` 的含义。

在固定正值 `Q/R` 下，该递推的稳态后验方差满足：

$$
P_\infty=\frac{-Q+\sqrt{Q^2+4QR}}{2}.
$$

据此得到示例参数下的稳态增益约为 `0.2702`。这是该标量模型的解析值，可用于理解更新权重；台架上的响应还包含采样、量化和压力系统本身的动态。

滤波与 PID 的微分项共同影响高频反馈。较强平滑会降低短时读数波动，同时引入跟踪滞后，调参时应联合观察阶跃响应与控制量。

## 反馈控制

### 离散 PID

[`pid_controller_calculate`](../main/algorithms/pid_controller.c) 从毫秒时间戳计算 `dt`，并设置 `0.001 s` 的下界。令 `e_k = r_k - y_k`，实际更新为：

$$
I_k=\operatorname{clip}\left(I_{k-1}+e_kdt,\ -u_{max}/K_i,\ u_{max}/K_i\right),
$$
$$
D_k=\frac{e_k-e_{k-1}}{dt},\qquad
u_k=\operatorname{clip}(K_pe_k+K_iI_k+K_dD_k,\ u_{min},u_{max}).
$$

积分采用限幅方法，输出单独进行饱和。当前初始化使用 `Kp=20`、`Ki=2`、`Kd=1`，输出区间 `[0,4095]`。积分上限公式要求正的 `Ki`，零积分增益需要单独处理。公式中的参数属于软件初始配置。

微分项基于误差差分，目标阶跃也会进入微分项；工作周期切换时通过 `pid_controller_reset` 清空积分、历史误差并更新时间。初次更新与重新启动时的控制量需要单独观察。

### 执行器映射与符号

[`run_continuous_mode`](../main/npwt_logic.c) 将控制量转换为：

$$
d_k=4095-\operatorname{uint16}(u_k).
$$

随后按配置上下界限制 `d`，并调用 [`hal_pump_set_duty`](../main/hal/hal_pump.c) 写入 PCA9685。代码把较小计数解释为较大泵作用、把 `4095` 用作停止命令；实际效果取决于外部驱动电路的极性和 PWM 电平。

压力以负值表示，误差采用“目标减反馈”，PID 输出又限制为非负，三者需要一起验证。例如目标 `-20`、反馈 `0`、积分和历史误差均为零时，PID 输出被截到 `0`，映射为 `4095`。这个计算结果给出了台架上首先需要核对的控制方向。

`NPWT_PWM_WORKING_MAX` 在配置中定义为 `1638`，当前连续模式实际约束使用 `NPWT_PWM_MAX` 和 `NPWT_PWM_WORKING_MIN`。说明和测试应按调用路径中生效的参数记录。

控制器使用常量规模的标量计算。系统的时间开销主要还包括 ADC、I2C、互斥锁等待及界面更新。

## 任务与状态

### 调度节拍

控制任务执行“采样 → 滤波 → 模式动作”，释放共享数据锁后调用 UI 更新接口，最后执行 `vTaskDelay(100 ms)`。该写法的实际周期包括工作耗时和延时，名义更新频率约为 10 Hz。PID 使用实测调用间隔，而模式计时由独立 1 秒软件定时器完成。

UI 回调通常每 1 秒更新一次，强制刷新可提前触发。LVGL 锁和核心数据锁分别保护界面对象与控制状态；压力反馈计算在 UI 回调前完成。两个核心 getter 分别返回设置和运行数据副本，跨结构的一致快照需要额外协调。

### 连续与间歇模式

| 当前状态与事件 | 状态更新 | 动作 |
| --- | --- | --- |
| 连续模式且开机 | 工作 | 每轮执行滤波后的反馈控制。 |
| 间歇模式从空闲启动 | 工作，工作计时清零 | 执行连续模式的控制动作。 |
| 工作时间达到设定值 | 休息，休息计时清零 | 提交停止泵命令。 |
| 休息时间达到设定值 | 工作，工作计时清零 | 重置 PID 并恢复控制。 |
| 关闭运行 | 空闲 | 提交停止泵命令。 |

休息阶段的实现是停止泵输出。腔体压力如何回落取决于气路，主动泄压需要对应执行器和控制路径。上层声明还有 `ERROR` 状态；实际异常显示由 UI 桥接层的独立状态结构管理。

### 阈值与持续时间判断

[`npwt_ui_check_anomalies`](../main/npwt_ui_bridge.c) 实现了持续时间判定。开机后先经过 30 秒观察期；开启自动停止选项后，按以下代码条件计时：

| 条件 | 持续时间 | 处理 |
| --- | --- | --- |
| 当前压力在 `[-5,0]` 且目标 `< -10` | 5 秒 | 设置漏气提示并关闭运行。 |
| 当前压力 `< -30` | 5 秒 | 设置堵塞提示并关闭运行。 |

条件中断后相应计时清零。阈值、观察期和提示名称是原型中的工程规则，需要结合传感器位置、工作/休息模式和台架故障场景评估。

此检查位于 UI 更新路径，调用间隔受界面调度影响；自动停止选项默认关闭。独立保护回路、故障锁存和异常任务属于进一步的安全设计范围。

## 设置与硬件集成

[`npwt_core.c`](../main/npwt_core.c) 通过 NVS 保存目标压力、工作时间、休息时间和模式。设置加载阶段将运行开关置为关闭；随后 [`app_main`](../main/main.c) 会调用 `npwt_system_start`，UI 桥接初始化也包含 PWM 输出测试。因此首次调试需要先隔离执行器电源、核查启动路径和输出电平，再进入受控台架实验。

当前源码与构建清单的对齐项见[构建说明](build.md)，实验和故障检查见[验证说明](validation.md)。
